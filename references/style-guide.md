# 下周七 · 蓝色手帐网页视觉规范

本规范用于把已确认的蓝色手帐图片语言转换成真实 HTML。目标不是普通的浅蓝色网站，而是保留原图里的纸张、手写标记、照片拼贴与海报式阅读节奏，同时让网页在手机上稳定、清楚、可滚动。

## 1. 视觉气质

核心感受：清透、温柔、有序、好看。

- 像晴天天空与白云，而不是灰蓝后台界面。
- 像认真整理的生活手帐，而不是堆满贴纸的素材板。
- 像一张可以阅读的教程海报，而不是企业官网或 SaaS 落地页。
- 细节有手作感，信息仍保持清楚、轻松和克制。

## 2. 配色系统

| 角色 | 建议颜色 | 用法 |
| --- | --- | --- |
| 天空蓝 | `#CFE8FF` | 主背景、光晕、标题高亮 |
| 奶白色 | `#FFFFFF` / `#FFFEFA` | 纸张、卡片、留白 |
| 柔雾米 | `#FFF8E1` | 暖光和大面积浅色过渡 |
| 浅灰蓝 | `#E8EEF5` | 次级纸卡、分层背景 |
| 深蓝灰 | `#263D55` | 标题和正文，不使用大面积纯黑 |
| 手写蓝 | `#4A98CC` | 箭头、勾选框、波浪线、编号 |
| 奶油黄 | `#FFE9A0` | 便利贴与唯一重点提示 |
| 辅助绿 | `#BFE4C6` | 小型波浪线或柔和提示 |
| 柔橙红 | `#D85B4E` | 指向真实操作入口的少量箭头 |

蓝、白、浅灰蓝应占画面约 80%。黄色、绿色和柔橙红只负责提示，不形成第二套主色。

## 3. 背景与材质

背景需要同时包含：

- 天空蓝到奶白、柔雾米的渐变；
- 2–4 个边缘模糊的白色云雾光斑；
- 很轻的纸张或颗粒纹理；
- 至少一个偏暖的柔光区域，让页面不显冷硬。

不能只用纯色背景，也不要用深色蒙层、强玻璃反射、霓虹渐变或大面积灰色。

## 4. 三种参考结构

### A. 风格总览页

适合设计规范、功能总览、多个模块的知识卡：

1. 顶部中央放大标题和短英文副标。
2. 左上使用胶带纸条；右上使用手写英文和拍立得。
3. 中部以不完全对称的双栏布局组织卡片与手机主视觉。
4. 编号圆章统一 1–4，模块分别表达配色、元素、版式和适用场景。
5. 底部用小花、一句手写收尾和细英文结束。

### B. 教程步骤页

适合单个步骤或操作路径：

1. 顶部使用编号圆章 + 大标题 + 波浪线 + 小星星。
2. 左侧放短步骤、勾选框和虚线路径卡。
3. 右侧放一个清晰的手机截图或设备模型。
4. 橙红箭头只能指向真实入口。
5. 底部用黄色便签和白色手绘气泡补充提示。

### C. 教程封面页

适合问题型标题、App 技巧或知识入口：

1. 顶部放小栏目标签与“建议收藏”等弱提示。
2. 大标题分为 2–4 行，关键短语使用浅蓝笔刷底纹。
3. 标题下方只放一句简短解释，并用浅绿波浪线收住。
4. 下半区使用一张信息纸卡和一个手机截图形成左右错落。
5. 黄色便签压在手机截图下方，作为结论或入口提示。

## 5. 元素规范

### 圆角纸卡

- 使用半透明奶白或白色。
- 边缘有很淡的白色描边。
- 阴影柔软、宽而浅，偏蓝灰，不做悬浮按钮感。
- 圆角较大但保持纸张感觉，避免塑料胶囊感。

### 编号圆章

- 天空蓝渐变，内侧有轻微高光。
- 数字使用白色手写或圆润字体。
- 阴影小于纸卡阴影，不能成为立体徽章。

### 便利贴与胶带

- 一页通常只出现 1 张主便利贴。
- 胶带使用半透明蓝或米黄，允许轻微旋转。
- 便利贴承担提示或结论，不能承载长篇正文。

### 手写标记

- 波浪线、箭头、星星、爱心、勾选框保持线条感。
- 颜色以手写蓝为主，必要时用柔橙红强调真实路径。
- 每个内容区域控制在 1–2 个装饰标记。

### 拍立得与照片

- 图片四周保留较宽白边，下边可以写一行短句。
- 允许 3°–8° 的轻微旋转与顶部胶带。
- 旅行照片只作为页面的一个模块，不能取代全部网页结构。

### 手机截图

- 优先使用用户提供的真实截图。
- 保留关键入口与文字清晰度；涉及隐私先遮挡。
- 可裁出手机或截图区域嵌入页面，不能凭记忆伪造操作界面。
- 一张海报式页面只设置一个主设备或主截图。

## 6. 字体与信息层级

- 主标题：圆润黑体、自然手写体或轻杂志感字体。
- 正文：清楚的黑体或辨识度高的手写体。
- 英文副标：轻巧无衬线或自然手写体。
- 主标题用深蓝灰；正文略浅；说明字使用手写蓝。
- 避免大卖场、促销海报、厚重立体字、强描边和密集文字块。

阅读顺序应始终明确：小标签或编号 → 大标题 → 一句解释 → 主视觉 → 提示收尾。

## 7. HTML 实现规则

### 基础容器

```css
* { box-sizing: border-box; min-width: 0; }
html, body { width: 100%; max-width: 100%; margin: 0; overflow-x: hidden; }
img { display: block; max-width: 100%; }
```

### 海报式页面

```css
.poster {
  width: min(920px, calc(100vw - 12px));
  aspect-ratio: 3 / 4;
  position: relative;
  overflow: hidden;
  container-type: inline-size;
}
```

海报内部优先使用百分比定位与 `cqw`（容器查询宽度单位），让文字、圆角、装饰和阴影一起缩放。所有旋转、阴影和绝对定位元素必须被海报容器裁住。

### 手机端禁止横向移动

- 不要让主容器同时使用 `100vw` 和额外左右 padding。
- 不要把装饰元素定位到画布外，再依赖 `body { overflow-x: hidden; }` 掩盖问题。
- 检查长英文、`white-space: nowrap`、固定像素宽度、负 margin、transform 和阴影。
- 在 375–390 px 宽度下验证：`document.documentElement.scrollWidth <= document.documentElement.clientWidth`。
- 页面只允许纵向滚动；需要横向展示的内容必须改为换行、缩放或卡片堆叠。

### 无脚本可见

正文与主要图片默认可见。若添加入场动画，应先显示内容，再在浏览器确认支持脚本后添加动画类。脚本失败时不能出现空白页面。

## 8. 响应式策略

- 海报母版：保持 3:4 比例，使用容器单位等比缩放。
- 连续网页：桌面可使用双栏，手机端切为单栏。
- 手机端正文不小于可辨识尺寸；若 3:4 海报信息过多，应拆成多个页面，不要继续压缩文字。
- 图片使用 `object-fit` 和明确的裁切区域，避免人物、截图入口或文字被切掉。
- 所有交互目标保持适合触摸，焦点状态清楚。

## 9. 禁止项

- 把参考图直接当网页背景或整张图片输出。
- 用普通企业官网导航、数据后台、SaaS 首屏代替手帐布局。
- 大面积高饱和青蓝、紫蓝霓虹、黑色阴影或玻璃塑料质感。
- 复制示例里的 App Store 文案到无关主题。
- 随意增加 Logo、账号名、按钮、营销口号或说明性设计文字。
- 让页面在手机端左右滑动。

## 10. 交付检查

- HTML 是真实可编辑结构，不是截图壳。
- 参考图中的主要视觉语言在首屏即可识别。
- 所有真实信息、路径和截图保持准确。
- 蓝白清透，不灰、不脏、不荧光。
- 装饰服务于信息，没有压住标题或截图。
- 375、390、768 与桌面宽度均无横向溢出。
- 关闭 JavaScript 后页面仍有完整内容。
- 图片具有替代文本，标题层级合理。
